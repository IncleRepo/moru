# 작동 구조

Moru는 요청을 직접 처리하는 실행 조정자입니다. 프로젝트 규칙과 사용자의 범위를 유지하면서 필요한 전문 스킬과 도구를 고르고, 작업 결과를 검증해 하나로 정리합니다.

## 처리 흐름

```text
사용자 요청
  → 작업 범위와 완료 조건 확인
  → 프로젝트 문서와 MORU.md 확인
  → 전문 스킬과 도구 선택
  → 직접 실행 또는 독립 작업 분리
  → 결과 통합과 검증
  → COMPLETE / PARTIAL / BLOCKED 보고
```

### 1. 요청 범위 확인

구현, 리뷰, 조사처럼 요청의 성격을 구분하고 수정 가능 여부와 외부 작업 범위를 확인합니다. 리뷰만 요청했다면 수정으로 확대하지 않습니다.

### 2. 프로젝트 문맥 확인

현재 요청에 첨부된 자료를 먼저 보고, 프로젝트의 `MORU.md`와 공식 규칙을 확인합니다. 필요한 정보가 부족한 경우에만 현재 프로젝트 안에서 탐색 범위를 넓힙니다.

### 3. 작업에 맞는 기능 선택

문서, 코드, 데이터베이스처럼 작업 분야에 맞는 설치된 전문 스킬과 전용 도구를 우선합니다. 프로젝트의 `Skills` 설정은 선택 기준으로 사용하지만 요청 범위나 권한을 바꾸지는 않습니다.

### 4. 실행 방식 결정

하나의 흐름이면 직접 처리합니다. 순서가 정해진 작업은 단계별로 진행하고, 서로 결과나 수정 영역이 겹치지 않는 작업만 실행 환경이 허용할 때 병렬로 나눕니다. 최종 결과를 합치고 판단하는 책임은 Moru가 유지합니다.

### 5. 검증과 완료 판단

파일이 만들어졌다는 사실만으로 완료하지 않습니다. 코드에는 관련 테스트와 빌드, 문서에는 렌더링과 대상 위치 확인처럼 결과에 맞는 검증을 적용합니다. 검증할 수 없는 항목은 완료한 것처럼 보고하지 않습니다.

## 지침의 역할

- 사용자 요청은 현재 작업의 목표와 범위를 정합니다.
- 프로젝트 공식 규칙은 구현과 결과가 따라야 할 제약입니다.
- `MORU.md`는 반복해서 사용할 자료와 기본 선택을 연결합니다.
- 전문 스킬은 분야별 작업 절차를 담당합니다.
- Moru는 이 정보를 조정하고 결과를 통합·검증합니다.

문서나 스킬 이름을 등록하는 행위는 배포, 삭제, 운영 데이터 변경 같은 추가 권한을 만들지 않습니다. 필요한 권한이나 필수 정보가 없으면 가능한 독립 작업까지만 끝내고 남은 조건을 알립니다.
